# 软件设计师备考学习流

核心原则：**最小考点循环 + 自适应题组 + 真题校准 + 间隔复习 + Study Transaction（学习事务）**。

状态：`⬜ 未开始` ｜ `🟦 学习中/教学完成但待校准` ｜ `🟨 初步掌握，待延迟复测` ｜ `✅ 延迟复测通过`。

## 0. 状态文件架构

长期学习状态使用小文件分片，禁止把持续增长的大文件作为高频写入事实源。

- 全局浏览入口：`00-学习计划/总体进度.md`。只放 01～12 模块概况和冲刺状态，保持简短。
- 唯一恢复入口：`00-学习计划/当前检查点.md`。保存当前模块、上层考点、最小子考点、阶段、最后完成项、下一动作、校准债务、更新时间。每次开始/继续/答题/复测/保存/查看进度都先读它。
- 模块状态事实源：`00-学习计划/模块进度/01-...md` ～ `12-...md`。**01～12 文件必须长期全部保留，即使尚未学习也要保留其完整计划清单；进入新章节不是创建/替换旧章节，而是更新对应模块文件。**
- 学习日志：按日期分片为 `15-学习日志/YYYY-MM/DD.md`。当天不存在则创建；存在则完整读取确认未截断后更新。
- 知识本体：继续写入对应章节目录的考点笔记。

### 旧文件保护门禁

`00-学习计划/进度跟踪.md` 与 `15-学习日志/日志.md` 是迁移前历史档案，**保留且不得删除、清空、覆盖为摘要或移动，除非用户未来明确要求清理旧结构。** 它们不再作为每个最小考点的高频写入事实源，也不得优先于新的检查点和模块进度。迁移/重构操作默认只能新增分片文件，不得以“整理”为理由删除旧文件。

职责分离：知识点笔记回答“学了什么”；模块进度回答“掌握到哪”；当前检查点回答“下一次从哪继续”；日期日志回答“今天发生了什么”；总体进度回答“全局大概到哪”。

## 1. 启动检查（每次进入必做）
1. 读 `00-学习计划/当前检查点.md`。
2. 根据其中模块读取对应 `00-学习计划/模块进度/<模块>.md`。
3. 读 `14-错题本/README.md` 复习队列，优先处理今天到期/逾期错题，默认 10–20 分钟。
4. 必要时读当天日期日志交叉核对。
5. 若检查点与模块状态冲突，以能被远端最新提交和知识点笔记共同验证的更具体状态为准，并先修复状态文件。
6. 报告当前定位和到期复习，等用户“开始”。用户说“继续”时精确恢复，不从头讲。

## 2. 最小考点粒度门禁
一个进度项若包含多个可独立命题概念，必须拆成最小子考点。名称中有“、”“/”“+”并列、同时含不同题型、任一部分可独立成为真题主考点、或完整讲解需要超过一组验收题时，默认拆分。拆分结果先写入当前模块进度文件，只定位第一个子考点。一次只讲当前最小子考点，不提前展开后续考点。

## 3. 考点级循环

### 步骤 1 · 定位
报告模块和最小子考点，等用户“开始”。

### 步骤 2 · 讲解
固定四段：定义、要点、易错点、真题考法。必须包含完整推导/案例，不只列规则。上午章节以文字、公式、小例子为主；下午算法/UML/模式优先使用 Java 或 UML/图示。结束后问是否深入或进入问答。

### 步骤 3 · 问答
持续澄清，用户确认无问题后再进入答题。

### 步骤 4 · 答题
自适应题组从 5 题起：2 即时理解 + 2 变式 + 1 综合迁移，逐题作答、批改、解析。0 错且理由正确进入校准；1 错/理由不完整追加 2 道针对变式；≥2 错先补讲再追加 3–5 题；同类错误连续出现则停止堆题先补讲。

知识性错题立即进入错题本并排 D+1/D+3/D+7/D+14；当场补强不等于延迟复测。

#### 真题校准
每个子考点目标至少 2 道已核验“考生回忆版真题”。必须可追溯到明确年份/场次页面；不得凭模型记忆编造年份、题号。题源未明确声明回忆版时只能标为外部校准/仿真/出版练习。

真题来源不足只阻塞状态升级，不阻塞新授：若自适应题组、主要命题模型、错因补强、笔记和 Study Transaction 都完成，则保持 `🟦 待真题校准` 并允许进入下一考点。满足自适应 + ≥2 道合规回忆版真题 + 命题模型覆盖后可升 🟨。

### 步骤 5 · 个人记忆点
主动问用户是否有记忆点；用户说“没了”结束。记忆点写入考点笔记 `## 我的笔记`，形式为一句话 + 标签（判据/口诀/易错/疑问）+ 可选原因/例子。

## 4. Study Transaction（强制学习事务）
每个最小子考点教学闭环结束后，必须执行一次完整事务。**事务完成前禁止宣布考点已发布、禁止定位或讲解下一新考点。**

一次事务必须全部完成：
1. 创建/更新当前知识点笔记；
2. 更新当前模块进度文件；
3. 更新 `00-学习计划/当前检查点.md`，指向下一最小子考点及正确阶段；
4. 创建/更新当天 `15-学习日志/YYYY-MM/DD.md`；
5. 若有错题，更新错题本/复习队列；若有合规回忆版真题，更新真题索引；
6. commit/push 到远端；
7. **从远端重新读取 `当前检查点.md` 和当前模块进度文件验证**；必要时回读当天日志/笔记。

只有 1～7 全部成功，才允许说“本考点已完成”“已沉淀并发布”“下一考点是……”。某个 create/update/commit 单独成功不代表事务成功。任一步失败：事务视为未提交；保持当前检查点；优先修复；不得开始下一新授。

### 4.1 两类债务不得混淆
- 教学/验收债务：缺合规回忆版真题、待延迟复测。可以保持 🟦/🟨 并按规则继续主线。
- 状态提交债务：笔记、模块进度、检查点、日志、错题/真题索引、push 或远端验证未完成。属于事务失败，禁止推进。

## 5. GitHub Connector 安全规则
1. 高频状态必须使用上述小文件分片。
2. 禁止根据被截断的长文件内容执行整文件覆盖；工具返回 truncated/截断时，不得把该内容作为完整文件传给 `update_file`。
3. 优先更新当前模块、当前日期和当前检查点对应的小文件。
4. 不得因为旧大文件难以更新而跳过 Study Transaction。
5. 远端回读验证是提交门禁的一部分，不得省略。
6. **任何重构默认不得删除旧进度/旧日志或任何历史学习文件。**
7. commit message 优先使用中文或清晰的 study/refactor 前缀。

## 6. 间隔复习
错题按 D+1 → D+3 → D+7 → D+14 复测，必须换题且脱离原解析。连续通过才升级/归档；失败则回退并重新排队。🟨 不作为未完成新授重复讲解。

## 7. 查看进度
用户问“进度到哪/查看进度”时：先读 `总体进度.md` + `当前检查点.md`，再读当前模块进度；需要跨章节细节时再读取对应 01～12 模块文件。报告已完成主线、活动错题/复测债务、真题校准债务、当前检查点和下一步。旧全局进度表只作兼容参考。

## 8. 发布与完整性原则
知识库是长期学习状态的唯一事实来源。会话记忆只能辅助，不得替代仓库状态。每次 Study Transaction 后必须远端验证；若仓库状态与会话冲突，先修复仓库再继续。
