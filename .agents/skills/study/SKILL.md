# 软件设计师备考学习流

核心原则：**最小考点循环 + 自适应题组 + 真题校准 + 间隔复习 + Study Transaction（学习事务）**。

状态：`⬜ 未开始` ｜ `🟦 学习中/教学完成但待校准` ｜ `🟨 初步掌握，待延迟复测` ｜ `✅ 延迟复测通过`。

## 0. 状态文件架构

长期学习状态使用小文件分片，禁止把持续增长的大文件作为高频写入事实源。

- 全局浏览：`00-学习计划/总体进度.md`。
- 唯一恢复入口：`00-学习计划/当前检查点.md`。
- 模块事实源：`00-学习计划/模块进度/01-...md` ～ `12-...md`；01～12 必须长期全部保留。
- 学习日志：`15-学习日志/YYYY-MM/DD.md`。
- 知识本体：对应章节目录的考点笔记。
- **错题调度入口：`14-错题本/当前复习队列.md`。启动时只读轻量队列，不再扫描旧大 README。**
- 错题索引：`14-错题本/错题索引.md`。
- 新版活动错题详情：`14-错题本/活动错题/错NNN.md`；归档目录：`14-错题本/已归档/`。

### 旧文件保护门禁
`00-学习计划/进度跟踪.md`、`15-学习日志/日志.md`、`14-错题本/README.md`、`14-错题本/README-archive-*.md`、既有 `复测-*.md` 等迁移前历史档案必须保留。**不得删除、清空、覆盖成摘要或移动，除非用户未来明确要求。** 新结构采用兼容读取/懒迁移，不要求一次性搬空历史。

## 1. 启动检查（每次进入必做）
1. 读 `00-学习计划/当前检查点.md`。
2. 读当前模块 `00-学习计划/模块进度/<模块>.md`。
3. 读 `14-错题本/当前复习队列.md`，先处理今天到期、逾期或明确标记高优先级待重排的活动错题，默认 10–20 分钟。
4. **只对本轮实际要复测的错题读取详情。** 优先读 `活动错题/错NNN.md`；若尚未迁移，则按需读取旧 README/归档 README/相关 `复测-*.md`，并可在本轮事务中懒迁移为独立文件。不得为找一题扫描/重写全部历史。
5. 必要时读当天日期日志交叉核对。
6. 检查点、模块状态、队列冲突时，以远端最新、具体且可被知识点/复测历史验证的记录为准，先修复再继续。
7. 报告到期复习和当前新授定位，等用户“开始”。用户说“继续”时精确恢复。

## 2. 最小考点粒度门禁
一个进度项若包含多个可独立命题概念，必须拆成最小子考点。名称中有并列概念、同时含不同题型、任一部分可独立命题、或需要超过一组验收题时默认拆分。拆分结果先写当前模块文件；一次只讲当前最小子考点。

## 3. 考点级循环

### 步骤 1 · 定位
报告模块和最小子考点，等用户“开始”。

### 步骤 2 · 讲解
固定四段：定义、要点、易错点、真题考法。必须有完整推导/案例。上午章节以文字/公式/例子为主；下午算法/UML/模式优先 Java 或 UML/图示。一次只展开当前最小子考点。

### 步骤 3 · 问答
持续澄清，用户确认无问题后进入答题。

### 步骤 4 · 答题
自适应题组从 5 题起：2 即时理解 + 2 变式 + 1 综合迁移，逐题作答、批改、解析。0 错进入校准；1 错追加 2 道针对变式；≥2 错先补讲再追加 3–5 题；同类错误连续出现则先补讲。

#### 新错题写入（能力保持不变，存储改为分片）
知识性错误立即：
1. 分配下一个 `#错NNN`；
2. 创建 `14-错题本/活动错题/错NNN.md`，记录模块、考点、首次错误日期、原错因、正确判据、当场补强和复测历史；
3. 把该编号加入 `当前复习队列.md`，安排 D+1 → D+3 → D+7 → D+14；
4. 更新 `错题索引.md`；
5. 当场补强可记录，但**不计延迟复测通过**。

#### 真题校准
每个子考点目标至少 2 道已核验考生回忆版真题；必须可追溯明确年份/场次，不得凭模型记忆编造。来源不足只阻塞状态升级，不阻塞新授：教学闭环和 Study Transaction 完成后保持 `🟦 待真题校准` 可继续；满足自适应 + ≥2 道合规回忆版 + 命题模型覆盖后可升 🟨。

### 步骤 5 · 个人记忆点
主动询问；用户说“没了”结束。写入考点笔记 `## 我的笔记`。

## 4. 错题延迟复测（原能力必须保持）

### 4.1 调度
复测阶梯保持：**D+1 → D+3 → D+7 → D+14**。队列应记录下一复测日期/阶段；历史迁移项若日期无法可靠恢复，写“待重排”，不得猜日期。

### 4.2 出题门禁
- 必须脱离原解析，使用同错因的**换题**；不得直接重复原题或提前暴露答案。
- 复测前读取该错题详情及必要的知识点笔记，但给用户的题不能泄露旧解析。
- 同日补强永远不计延迟通过。

### 4.3 通过、失败与归档
- 每次延迟换题答对：记录一次有效通过，并推进下一阶段。
- **连续两次延迟换题答对后才可标记 ✅ 归档**（保持旧规则）；D+1/D+3/D+7/D+14 仍作为调度阶梯使用，具体历史已有更严格计划时不得降级。
- 复测失败：清零/回退连续通过计数，记录错因，重新激活并重排延迟复测；同日可补强但不算延迟通过。
- 已归档知识若后续隔日再次答错：从归档状态重新激活，加入当前队列并重新安排延迟复测。
- 归档后从 `当前复习队列.md` 移除，更新 `错题索引.md`；有独立错题文件时标记归档。Connector 无安全 move 时允许保留原路径并标记归档，禁止为了移动而删除历史。

### 4.4 历史兼容 / 懒迁移
旧错题无需一次性搬迁。复测某个尚无独立文件的历史编号时：按需从旧 README/归档 README/复测日志提取**该题必要事实**，创建对应 `活动错题/错NNN.md` 后继续新流程。旧来源永远保留。

## 5. Study Transaction（强制学习事务）
每个最小子考点闭环或一次复测批次结束后，都必须提交完整事务；完成前禁止宣布发布完成或推进新考点。

最小子考点事务：
1. 知识点笔记；
2. 当前模块进度；
3. `当前检查点.md`；
4. 当天日期日志；
5. 若有新错/复测：独立错题文件 + `当前复习队列.md` + `错题索引.md`；若有合规真题：真题索引；
6. commit/push；
7. 远端回读验证 `当前检查点.md`、当前模块文件；涉及错题时还必须回读 `当前复习队列.md` 和本轮变更的错题详情。

只有全部成功才能说“完成/已发布/下一考点”。某个 create/update/commit 成功不等于事务成功。任一步失败则事务未提交，优先修复，不得推进。

### 两类债务不得混淆
- 教学/验收债务：缺合规回忆版、待延迟复测，可按规则继续主线。
- 状态提交债务：笔记/模块/检查点/日志/错题队列/索引/push/回读缺失，属于事务失败，禁止推进。

## 6. GitHub Connector 安全规则
1. 高频状态使用小文件分片。
2. 工具返回 truncated 时禁止把该内容作为完整文件 `update_file`。
3. 优先定点读取/更新当前模块、当天日志、当前队列和本轮错题详情。
4. 不得因旧大文件难更新而跳过事务。
5. 远端回读验证不得省略。
6. 任何重构默认不得删除旧进度、旧日志、旧错题 README、历史复测文件或其他学习历史。
7. commit message 优先中文或清晰的 study/refactor 前缀。

## 7. 查看进度
“查看进度”：读 `总体进度.md` + `当前检查点.md` + 当前模块；需要跨章节再按需读模块文件。“查看错题/复测进度”：先读 `当前复习队列.md` + `错题索引.md`，再只读用户关心的独立错题详情；历史未迁移项按需兼容读取旧文件。

## 8. 发布与完整性原则
知识库是长期学习状态唯一事实来源。会话记忆只能辅助。仓库与会话冲突时先修复仓库；每次 Study Transaction 后必须远端验证。
