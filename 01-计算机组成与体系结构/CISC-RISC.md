# CISC / RISC

> 模块：01 计算机组成与体系结构 ｜ 状态：✅ ｜ 2026-07-07 完成

## 定义
CISC（复杂指令集）与 RISC（精简指令集）是 CPU 指令集设计的两种哲学：CISC 让硬件干多（复杂指令、减少条数），RISC 让编译器干多（简单指令、靠流水线提速）。

## 要点（含案例）

### 为什么有这两条路子
- 早期内存贵慢 → CISC：一条指令干多事，减少指令条数、少跑取指令。复杂指令靠微码实现。
- 后来发现 ~80% 时间跑 ~20% 简单指令，复杂指令少用且难流水 → RISC：回归简单、固定长度、单周期、能流水，优化压力甩给编译器。

### 一个例子看懂（内存加法 C=A+B）
```
CISC:  ADD [C],[A],[B]                                    ← 1 条复杂指令，直接内存到内存加法
RISC:  LOAD R1,[A] / LOAD R2,[B] / ADD R3,R1,R2 / STORE [C],R3   ← 4 条简单，ADD 只操作寄存器
```
CISC 代码短但难流水；RISC 代码长但 4 条能流水并行。

### 对比表（核心）
| 维度 | CISC | RISC |
| --- | --- | --- |
| 指令数量 | 多 | 少 |
| 指令复杂度 | 复杂（可多步、可访存） | 简单（多为单周期） |
| 指令长度 | 可变 | 固定 |
| 寻址方式 | 多 | 少 |
| 访存指令 | 各种指令都可访存 | 只有 LOAD/STORE |
| 寄存器 | 少 | 多 |
| 控制方式 | 微程序（微码） | 硬布线 |
| 流水线 | 难 | 易 |
| 编译 | 简单 | 复杂 |
| 目标代码 | 短 | 长 |
| 代表 | x86 | ARM、MIPS |

## 易错点
1. **控制方式别反**：CISC 微程序 / RISC 硬布线。
2. **"只有 LOAD/STORE 访存"是 RISC 标志**：算术指令只操作寄存器。
3. **"目标代码短"是 CISC 优势，不是 RISC**：CISC 一条干多事→短；RISC 简单指令多→长。
4. RISC 指令**固定长度**、CISC **可变长度**。
5. RISC 寄存器**多**、CISC **少**。
6. RISC ≠ 绝对更快，靠流水线 + 高主频提速。

## 我的笔记
- [#N13] 判据 ｜ 控制方式（最易反）：CISC 微程序 / RISC 硬布线
  理: CISC 复杂指令靠微码实现→微程序；RISC 简单单周期→硬布线组合逻辑
- [#N14] 判据 ｜ 访存：RISC 只有 LOAD/STORE，算术指令只操作寄存器
  例: RISC 的 `ADD R3,R1,R2` 不访存；CISC 的 `ADD [C],[A],[B]` 可直接访存
- [#N15] 判据 ｜ 长度对比：代码长度 CISC 短/RISC 长；指令长度 CISC 可变/RISC 固定
  理: CISC 一条干多事→代码短但指令变长；RISC 简单固定→代码长但易流水
- [#N16] 口诀 ｜ CISC 多杂变微程序代码短；RISC 少简定硬布线流水线 load-store 寄存器多代码长
