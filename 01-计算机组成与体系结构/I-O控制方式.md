# I/O 控制方式

> 模块：01 计算机组成与体系结构 ｜ 状态：✅ ｜ 2026-07-15 完成（总线与 I/O ②/③）

## 定义
I/O 控制方式 = CPU 管理 I/O 的方式，按 CPU 介入程度递减：程序查询、程序中断、DMA、通道。

## 要点（含案例）

### 四种方式
| 方式 | CPU 介入 | 传输谁做 | 数据路径 | 适合 | 效率 |
| --- | --- | --- | --- | --- | --- |
| 程序查询 | 全程 | CPU | 设备↔CPU↔内存 | 低速偶发 | 最低 |
| 程序中断 | 每次完成介入 | CPU | 设备↔CPU↔内存 | 中速少量 | 中 |
| DMA | 仅首尾 | DMAC | 设备↔内存（不经 CPU） | 大批量高速 | 高 |
| 通道 | 仅发命令 | 通道（专用处理器） | 设备↔内存 | 大量设备 | 最高 |

### 关键区分
- **程序查询**：CPU 全程轮询等待，利用率最低。
- **程序中断**：CPU 启动后干别的，I/O 完成发中断通知；每传一字 CPU 介入一次。
- **DMA**：设备↔主存直传（DMAC 完成，周期窃取 / 独占总线），CPU 只首尾介入；整块完才通知一次 → 大批量。
- **通道**：专用 I/O 处理器，管一组设备多任务，CPU 只发启动命令；比 DMA 高级。

## 易错点
1. CPU 介入递减、效率递增：查询 > 中断 > DMA > 通道。
2. DMA 不经过 CPU：设备↔主存直传，CPU 只首尾。
3. DMA 适合大批量高速（磁盘）；中断适合中速少量。
4. 中断每次完成介入；DMA 整块完才介入一次 → DMA 更适合大批量。
5. 通道比 DMA 高级：DMA 一块，通道一组设备多任务。
6. 数据路径：查询/中断经 CPU；DMA/通道不经 CPU。
7. DMA 用周期窃取 / 独占总线传数据。

## 真题考法（上午单选）
- "CPU 介入最少"→ 通道。
- "DMA 特点"→ 不经 CPU 直传、大批量。
- "适合磁盘大批量"→ DMA。
- 介入 / 效率排序。
- 数据路径判别。

## 我的笔记
- [#N49] 口诀 ｜ 介入递减/效率递增：查询 > 中断 > DMA > 通道
  理: CPU 介入越少越能干别的→效率越高
- [#N50] 判据 ｜ DMA：设备↔内存直传、不经 CPU、CPU 只首尾、大批量高速（磁盘）
  理: DMAC 完成传输（周期窃取/独占总线），数据不进 CPU 寄存器
- [#N51] 判据 ｜ 通道：专用处理器、管一组设备、CPU 只发命令（比 DMA 高级）
  理: DMA 管一块数据，通道管一组设备多任务
- [#N52] 判据 ｜ 数据路径：查询/中断经 CPU；DMA/通道不经 CPU（设备直连内存）
  例: 查询/中断 设备↔CPU↔内存；DMA/通道 设备↔内存
- [#N53] 判据 ｜ 中断每次完成介入；DMA 整块完才介入一次 → DMA 更适合大批量
  理: 中断每字一次中断处理；DMA 整块一次中断→大批量省 CPU 介入
