# 同步互斥：信号量与 PV 基础

> 模块：02 操作系统 ｜ 状态：🟦
>
> 当前已通过自适应题组与补强题，尚缺至少 2 道明确标注为考生回忆版的软件设计师真题校准。

## 定义

信号量是表示可用资源数量或事件完成状态的整型变量，只能通过原子操作 P、V 修改；P 用于申请资源或等待事件，V 用于释放资源或通知事件完成。

## 要点

### P、V 的经典定义

```text
P(S):
    S = S - 1
    if S < 0:
        当前进程阻塞

V(S):
    S = S + 1
    if S <= 0:
        唤醒一个等待进程
```

- `S > 0`：当前还有 `S` 个可用许可。
- `S = 0`：没有剩余许可，但当前也没有因该信号量而等待的进程。
- `S < 0`：其绝对值通常表示等待该信号量的进程数。
- P、V 必须是原子操作，执行过程不能被其他进程插入。

### 互斥

互斥解决“多个进程不能同时进入临界区”的问题。只有一个临界区许可时：

```text
mutex = 1

P(mutex)
访问共享资源
V(mutex)
```

第一个进程执行 P 后 `mutex=0`，可以进入；其他进程再执行 P 会使信号量小于 0 并阻塞。退出临界区时必须执行 V，否则许可不会归还。

### 同步

同步解决“两个动作必须按规定先后发生”的问题。例如必须先执行 A，再执行 B：

```text
S = 0

进程 P1: 执行 A → V(S)
进程 P2: P(S) → 执行 B
```

若 P2 先运行，`P(S)` 会使 `S=-1` 并阻塞；P1 完成 A 后执行 V，使 `S=0`，并唤醒 P2 执行 B。

## 易错点

- P 是“先减一，再判断 `<0`”；V 是“先加一，再判断 `<=0`”，两个边界不同。
- V 后即使结果等于 0，也要唤醒一个等待进程。
- 单个临界区的互斥信号量初值是 1，不是 0。
- “不能同时做”是互斥；“必须先后做”是同步。
- 同步信号量通常初值为 0，由前序动作完成后执行 V 发出通知。
- P、V 必须成对放在正确位置；互斥场景遗漏 V 会使其他进程长期阻塞。

## 真题考法

- 给出信号量初值和一串 P/V 操作，判断最终值、阻塞数和唤醒数。
- 给出两个并发进程，填写信号量初值以及 P、V 的位置。
- 判断题目描述属于互斥还是同步。
- 将前趋关系转换成信号量约束；复杂的生产者—消费者、读者—写者和哲学家问题属于后续子考点。
