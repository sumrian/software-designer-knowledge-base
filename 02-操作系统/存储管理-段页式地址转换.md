# 存储管理：段页式地址转换

> 状态：🟨 初步掌握，待延迟复测  
> 学习日期：2026-08-10～2026-08-11

## 核心结构

段页式先按程序逻辑分段，再把每个段划分为固定大小的页；物理内存仍按页框分配。

逻辑地址：

```text
(段号 S，段内页号 P，页内偏移 W)
```

- 每个进程有一张段表。
- 段表项指向该段自己的页表，并记录段内页数或页表长度。
- 每个段有一张页表，记录“段内页号 → 物理块号”。

从物理角度看，段主要是一组页映射的逻辑归属；同一段的页可以位于离散物理块中。段保证逻辑组织，页表把逻辑连续伪装在物理不连续之上。

## 地址转换

```text
段号 S → 查段表 → 找到该段页表
段内页号 P → 查该页表 → 得到物理块号 F
物理地址 = F × 页大小 + W
```

完整边界检查：

1. `S < 段表项数`；
2. `P < 该段页数`；
3. `W < 页大小`。

> 段号找页表，页号找块号，块号乘页长，再加页内偏移。

页表地址指向映射表这种管理数据，不是逻辑段内容的统一物理基址。段内页分散存放，因此不能使用“段基址+段内地址”。

## 逻辑连续与物理离散

例如页大小 1024 B：

```text
段内页0 → 块7
段内页1 → 块2
```

段内逻辑地址 1023 和 1024 连续，但物理地址分别为：

```text
7×1024+1023 = 8191
2×1024+0    = 2048
```

所以逻辑连续不意味着物理连续。

## 访存次数

无 TLB，段表和页表均在内存且不缺页：

1. 访问段表；
2. 访问页表；
3. 访问目标数据。

共 3 次内存访问。若所需段表项已在专用寄存器中，仍需访问页表和目标数据，共 2 次。

## 地址字段容量

若字段位数分别为：

```text
段号 s 位
页号 p 位
偏移 w 位
```

则：

- 最多段数：`2ˢ`；
- 每段最多页数：`2ᵖ`；
- 页大小：`2ʷ B`。

字段表示容量上限，不代表每个段固定使用全部页面。

## 碎片

段内按页分配，不要求整个段占用连续物理空间，因此避免基本分段的外部碎片；但每个段的最后一页都可能产生内部碎片。

## 个人易错点

1. 检查段内页号时，必须读取段表中该段的页数，不能看错表或错行。
2. 三层边界都要检查，不能漏掉页内偏移。
3. 段表中的页表地址指向“地图”，不是段数据基址。
4. 最终物理地址仍用 `块号×页长+偏移`。
5. `9×2048+1800=20232`，此前算成 20132 属算术错误。
6. 专用寄存器、Cache 和 TLB 不是同一概念。
7. 同一段的逻辑页连续，但对应物理页框可以离散。
