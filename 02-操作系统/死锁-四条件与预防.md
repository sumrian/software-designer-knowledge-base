# 死锁：四条件与预防

> 状态：🟦 学习中，讲解、自适应题组与针对性补强已完成；待 2 道明确标注“考生回忆版”的真题校准。

## 一、死锁的定义

死锁是指一组进程因竞争资源而形成闭环等待：每个进程都占有部分资源，同时等待其他进程占有的资源，导致这组进程都无法继续推进。

需要区分：

- **普通等待**：等待条件将来可以被其他正常运行的进程解除。
- **死锁**：等待关系形成无法自行解除的闭环。
- **饥饿**：某个进程可能长期得不到资源，但系统中的其他进程仍在推进。

## 二、死锁的四个必要条件

| 条件 | 含义 |
| --- | --- |
| 互斥条件 | 某些资源一次只能由一个进程使用 |
| 请求并保持条件 | 进程保持已获得的资源，同时继续申请新资源 |
| 不可剥夺条件 | 资源只能由占有者主动释放，系统不能强制收回 |
| 循环等待条件 | 存在进程与资源构成的环形等待链 |

四个条件必须同时具备才**可能**发生死锁；缺少任一条件都不会死锁。但四条件具备只说明存在风险，并不等于当前已经死锁。对于多实例资源，或仍有环外进程能够释放资源的情况，等待仍可能被解除。

## 三、死锁预防

预防死锁的核心是破坏四个必要条件中的至少一个。

| 预防方法 | 破坏的条件 | 代价或局限 |
| --- | --- | --- |
| 共享资源、SPOOLing | 互斥条件 | 只适用于能够改造成共享方式的资源 |
| 运行前一次申请全部资源 | 请求并保持条件 | 资源利用率低，可能造成饥饿 |
| 申请失败时释放已有资源，或允许抢占 | 不可剥夺条件 | 只适合状态可保存、之后可恢复的资源 |
| 资源统一编号，按递增顺序申请 | 循环等待条件 | 申请顺序受限，编号设计可能不灵活 |

### 有序资源分配为什么有效

若所有进程只能按资源编号严格递增的方向申请，那么沿等待关系前进时，资源编号只能越来越大，不可能再回到较小编号形成闭环。

编号不必连续。例如先申请 1，再申请 4 是合法的；先申请 4，再申请 1 才违反递增规则。

### 哪些资源适合剥夺

- CPU：可以保存寄存器、程序计数器等上下文，之后恢复执行。
- 可换出的内存页：可以写回外存，需要时再调入。
- 打印机：打印产生不可逆的物理输出，不适合在任务中途强制回收，通常采用排队或 SPOOLing。

“保存并恢复”不是撤销已经完成的执行；CPU 本身也是物理资源，并非因为它是“虚拟资源”才可剥夺。

## 四、答题中暴露并修正的易错点

1. **四条件是必要条件，不是充分判据**  
   四条件同时存在意味着可能死锁，判断当前是否已经死锁还要分析资源实例数和等待关系是否能够解除。

2. **有序分配不要求连续编号**  
   只要求后申请资源的编号大于当前已持有资源的编号。

3. **可剥夺不等于回滚**  
   CPU 上的进程可保存现场并暂停，之后从保存点继续，不会撤销已经完成的计算。

4. **预防死锁不保证公平**  
   系统不存在死锁闭环，不代表每个进程都一定能及时获得资源。

## 五、个人记忆点

- **#N95｜四条件**：互斥、请求并保持、不可剥夺、循环等待必须同时具备，缺少任一条件都不会死锁。
- **#N96｜区别**：四条件具备表示存在死锁风险，不等于当前一定已经死锁；还要检查资源实例和等待关系能否解除。
- **#N97｜对应**：共享资源破互斥；一次申请破保持；失败释放破不可剥夺；统一编号破循环。
- **#N98｜有序分配**：编号不必连续，只要求每次后申请的资源编号更大。
- **#N99｜证明**：沿等待关系资源编号若严格递增，就不可能回到较小编号形成环。
- **#N100｜可剥夺资源**：CPU、内存页适合保存状态后暂停并恢复；不是撤销已完成的执行，也不是因为 CPU 是虚拟资源。
- **#N101｜不可剥夺资源**：打印输出具有不可逆物理结果，更适合排队或 SPOOLing，而非中途强制回收。
- **#N102｜死锁与饥饿**：预防死锁保证不存在相关进程全部停滞的闭环，但不自动保证单个进程公平获得资源。
