## 一、核心数据

| 数据 | 含义 |
| --- | --- |
| `Available` | 当前可用资源向量 |
| `Max` | 进程声明的最大资源需求 |
| `Allocation` | 已分配给进程的资源 |
| `Need` | 进程最多还可能需要的资源 |

```text
Need = Max - Allocation
```

## 二、安全性检查

1. 初始化 `Work=Available`，所有 `Finish[i]=false`。
2. 寻找尚未完成且满足 `Need[i]≤Work` 的进程。
3. 假设该进程完成并释放已占有资源：`Work=Work+Allocation[i]`。
4. 重复寻找；所有进程都能完成则存在安全序列，否则状态不安全。

向量比较要求每一种资源都满足。比较的是 `Need≤Work`，不是 `Max≤Work`。

进程完成后加的是 `Allocation`。它临时取得的 `Need` 在完成时同时归还，净增加来自它原先占有的资源。

## 三、安全、不安全与死锁

- 安全：存在一个保证所有进程完成的安全序列。
- 不安全：无法保证未来一定完成，存在走向死锁的申请方式。
- 死锁：相关进程当前已经因资源形成无法解除的等待关系。

进程即使处于不安全状态，只要没有申请新资源并阻塞，仍可执行普通计算。CPU 调度只决定哪个就绪进程运行，不能凭空增加资源。

> 不安全是未来可能走进死胡同；死锁是现在已经困在死胡同。

## 四、选择题技巧

1. 先计算全部 `Need`。
2. 检查每个选项的首进程，若 `Need≰Work` 可立即排除。
3. 每通过一个进程就更新 `Work+=Allocation`。
4. 安全序列可能不唯一，逐项验证题目要求的候选序列。

## 五、个人记忆点

- **#N103｜公式**：`Need=Max-Allocation`。
- **#N104｜判据**：安全性检查比较 `Need≤Work`，并且每一类资源都必须满足。
- **#N105｜回收**：进程完成后执行 `Work+=Allocation`，不是加 `Need`。
- **#N106｜区别**：不安全表示失去未来安全保证，不等于当前已经死锁。
- **#N107｜调度**：即使 `Available=0`，未等待资源的进程仍可能执行普通计算。
- **#N108｜排除**：安全序列选择题先看首进程，首步不满足即可快速排除。
