# 设备与作业：SPOOLing 原理与组成

## 定义

SPOOLing（假脱机）通过**磁盘作为中间存储区**，把用户进程与慢速、通常需要独占使用的 I/O 设备解耦。

核心效果可以记为：

> 用户/作业先把数据交给系统的磁盘中转区，再由专门的输入/输出进程与实际设备交互。

因此，用户进程通常不需要长期直接占有物理设备，也不必一直等待设备完成整个操作。

## 主要组成

### 输入井

- 通常位于磁盘。
- 用于暂存从输入设备预先读入的数据。
- 典型链路：`输入设备 → 输入进程 → 输入井 → 用户作业`。

### 输出井

- 通常位于磁盘。
- 用于暂存用户作业提交的输出结果。
- 典型链路：`用户作业 → 输出井 → 输出进程 → 输出设备`。

### 输入进程

负责把输入设备的数据送入输入井。

### 输出进程

负责从输出井取出待输出数据，并按系统安排送往实际输出设备。

## 高频判据

- **井在磁盘上**：输入井、输出井是外存中的中转区，不等同于普通内存缓冲区。
- **输入方向**：外部设备先进输入进程，再进入输入井。
- **输出方向**：用户作业先把数据放入输出井，再由输出进程送往设备。
- **提交不等于物理完成**：用户进程将打印任务提交到输出井后通常可以继续执行，不必等打印机真正打完。
- **逻辑共享不等于物理并行**：多个进程可以同时提交任务，但一台物理打印机仍按顺序执行打印任务。

## 易错点

1. 把输入链路和输出链路方向搞反。
2. 把“输出井 → 输出进程 → 输出设备”误写成“输出进程 → 输出井 → 输出设备”。
3. 误认为 SPOOLing 让一台物理打印机真正同时打印多个任务。
4. 误认为输入井/输出井位于内存；经典考法中它们通常位于磁盘。
5. 误认为用户进程必须等物理设备完成后才能继续。

## 记忆模型

把“井”理解成**中转仓库**，把输入/输出进程理解成**搬运员**：

- 输入：搬运员从外面取货，再放进仓库。
- 输出：用户先把货放进仓库，再由搬运员把货送出去。

所以输出方向固定记：

`用户作业 → 输出井 → 输出进程 → 输出设备`
