# 设备与作业：SPOOLing 虚拟设备与共享打印

## 定义

SPOOLing 可以把原本需要独占使用的物理设备，在用户看来变成可由多个进程共同使用的**虚拟共享设备**。

这里的“共享”是逻辑共享，不是让一台物理设备真正同时执行多个任务。

## 要点

以打印机为例：

`多个用户进程 → 提交打印任务 → 输出井排队 → 输出进程统一调度 → 物理打印机逐个执行`

因此：

- 多个进程可以并发提交打印请求。
- 用户进程不需要直接长期占有打印机。
- 打印任务先进入系统管理的磁盘中转区，由系统统一排队。
- 一台物理打印机同一时刻通常仍只执行一个任务。

## 虚拟设备的含义

“虚拟设备”不是复制出多台真实硬件，而是通过 SPOOLing 的中转与调度，使多个进程都获得“可提交设备请求”的逻辑使用能力。

经典结论：

**独占设备 → 逻辑上的共享虚拟设备。**

## 共享打印模型

例如系统只有一台打印机：

```text
P1 ─┐
P2 ─┼→ 输出井：[任务1][任务2][任务3] → 输出进程 → 打印机
P3 ─┘
```

P1、P2、P3 都可以提交任务，但真正物理打印仍由打印机按系统调度逐个完成。

## 易错点

1. 把“逻辑共享”误解成“物理并行”。
2. 误认为多个用户提交打印任务时，每个用户都直接占有打印机。
3. 误认为 SPOOLing 会复制出多台硬件设备。
4. 把方向说反，误记成“共享设备虚拟成独占设备”。
5. 误认为等待中的打印任务必须使对应用户进程一直阻塞。

## 高频判据

- 多个用户可以同时提交打印请求 → **逻辑共享**。
- 一台打印机依次完成多个任务 → **物理串行**。
- 将独占设备改造成共享的虚拟设备 → **SPOOLing 的典型效果**。
- 虚拟设备经典实现通常依赖 **SPOOLing + 磁盘**。
