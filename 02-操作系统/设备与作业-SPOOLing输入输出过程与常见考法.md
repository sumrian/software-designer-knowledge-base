# 设备与作业：SPOOLing 输入/输出过程与常见考法

## 定义

SPOOLing 在用户作业与慢速外设之间使用磁盘上的输入井、输出井作为中转区，并由专门的输入进程、输出进程负责数据搬运。

- 输入链路：`输入设备 → 输入进程 → 输入井 → 用户作业`
- 输出链路：`用户作业 → 输出井 → 输出进程 → 输出设备`

## 要点

- 输入进程负责把外部输入设备的数据送入输入井。
- 输出进程负责把输出井中的数据送往物理输出设备。
- 输入井、输出井通常位于磁盘，不是普通内存缓冲区。
- 用户作业提交输出后，通常无需等待物理设备实际完成后才继续执行，体现了用户作业与慢速外设的解耦。

## 易错点

### 1. 输入/输出方向混淆

只钉住两条专门进程职责：

- `输入设备 → 输入进程 → 输入井`
- `输出井 → 输出进程 → 输出设备`

记忆模型：

- 输入进程 = 收货员，把外面的货收进仓库。
- 输出进程 = 发货员，把仓库里的货送出去。

### 2. 把用户作业当成直接控制物理设备

SPOOLing 下，用户作业通常先与输入井/输出井交互，专门输入/输出进程再与物理设备交互。

## 常见考法

- 判断输入进程、输出进程职责。
- 判断输入井、输出井和物理设备的数据流方向。
- 对打印场景排序：`用户提交 → 输出井 → 输出进程 → 打印机`。
- 判断“用户必须等待打印机实际打印完成后才能继续”是否正确：典型 SPOOLing 语境下通常错误。
