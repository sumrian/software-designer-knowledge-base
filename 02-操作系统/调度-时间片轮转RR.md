# 调度：时间片轮转 RR

> 模块：02 操作系统 ｜ 状态：🟦（待第 2 道考生回忆版真题校准）

## 定义

时间片轮转（Round Robin，RR）按就绪队列顺序依次给进程分配固定长度的时间片；时间片耗尽仍未完成的进程回到就绪队列尾部。

## 要点

- RR 是抢占式调度：时间片到由时钟中断触发调度，当前进程由运行态转为就绪态并进入队尾。
- 进程在时间片用完前完成或主动等待 I/O，会提前释放 CPU，不必等满整个时间片。
- 时间片过大时，进程往往一次执行完，调度效果趋近 FCFS。
- 时间片过小时，响应更及时，但上下文切换频繁，调度开销增大。
- 若有 `n` 个持续就绪的用户、时间片为 `q`，忽略切换开销，一个完整轮转周期约为 `nq`。
- 若 `n` 个进程同时到达，队尾进程首次获得 CPU 前的等待时间为 `(n-1)q`；不要和完整轮转周期混淆。

## 易错点

- `q` 是一个进程单次占用 CPU 的时长，不是该进程相邻两次获得 CPU 的完整周期。
- 老真题可能把分时系统中每个用户的“响应时间”按完整轮转周期近似为 `nq`；严格区分时，队尾首次等待约为 `(n-1)q`。
- 时间片到使运行态转为就绪态，不是阻塞态；阻塞必须由等待事件或资源引起。
- 进程完成或阻塞时不会重新进入队尾，只有时间片耗尽且尚可运行时才进入队尾。

## 真题考法

- 判断时间片过大时 RR 会退化为何种算法。
- 根据时间片和进程数计算完整轮转周期、首次等待时间。
- 给出 CPU 执行时间，逐时间片追踪运行顺序和就绪队列变化。
- 结合完成、阻塞和新进程到达，判断下一次被调度的进程。
