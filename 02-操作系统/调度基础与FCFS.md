# 调度基础与 FCFS

> 模块：02 操作系统 ｜ 状态：🟦 待补足真题校准

## 定义

处理机调度是操作系统从就绪队列中选择一个进程并把 CPU 分配给它的过程。FCFS（First Come First Served，先来先服务）按进程进入就绪队列的先后顺序进行选择，通常属于非抢占式调度算法。

## 要点

### 调度对象与时机

- 处理机调度从就绪队列选择进程，不直接选择阻塞进程。
- 当前进程执行完成或主动阻塞后，需要选择新的就绪进程运行。
- 抢占式系统还可能在时间片到或更高优先级进程到达时重新调度。
- 某个阻塞进程被唤醒，不等于它立刻运行；它先进入就绪队列。

### 抢占与非抢占

- 非抢占式：运行进程通常持续执行到完成或主动阻塞，其他就绪进程不能强行夺走 CPU。
- 抢占式：操作系统可以暂停仍能继续执行的当前进程，把 CPU 分给另一进程。
- 出现可调度事件不一定马上发生进程切换，要结合调度方式判断。

### FCFS 规则

- 按进入就绪队列的顺序调度，通常使用 FIFO 队列。
- 不考虑进程工作量、优先级或紧急程度。
- 运行进程主动阻塞后，取就绪队列队首运行。
- 阻塞进程事件完成后重新进入就绪队列，通常排到队尾。
- FCFS 通常不会造成饥饿，但可能让后来的进程等待很久。

### 护航效应

若一个 CPU 工作量很长的进程排在多个短进程前面，所有短进程都要等待长进程，称为护航效应。FCFS 因此实现简单、调度开销小，但对短进程和交互式任务不友好。

## 易错点

- 释放设备只会使等待该设备的进程由阻塞态转为就绪态，不会使释放者自动让出 CPU。
- 被唤醒的进程不能跳过就绪态直接运行。
- FCFS 只看进入就绪队列的顺序，不会因为后来的进程更短而允许其抢占。
- 非抢占式不等于只能运行到正常结束；运行进程主动等待 I/O 时也会进入阻塞态并让出 CPU。
- “等待很久”和“永远得不到 CPU”不同；FCFS 通常无饥饿，但可能有严重护航效应。

## 真题考法

- 判断调度程序从哪种状态的进程中选择。
- 根据运行、就绪、阻塞状态和设备事件跟踪进程状态。
- 判断 FCFS 是否抢占以及就绪队列次序。
- 识别长进程阻塞多个短进程的护航效应。
