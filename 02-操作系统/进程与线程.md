# 进程与线程

> 模块：02 操作系统 ｜ 状态：🟦 待软件设计师回忆版真题校准

## 定义

进程是程序的一次动态执行过程，也是操作系统进行资源分配的基本单位；线程是进程中的执行路线，在支持线程的操作系统中，是处理机独立调度和执行的基本单位。

可以把进程理解为资源容器，把线程理解为容器中的执行路线。一个进程至少包含一个线程，也可以包含多个并发线程。

## 要点

### 资源归属与调度单位

- 进程拥有相对独立的地址空间、代码、数据、文件等资源，是资源分配的基本单位。
- 线程负责执行指令，是处理机独立调度和执行的基本单位。
- 在题目明确为“支持线程的操作系统”时，使用“进程管资源，线程受调度”这一判据。

### 同一进程内线程共享的内容

- 代码段和进程地址空间。
- 全局变量、数据段和堆。
- 进程打开的文件及大部分进程级资源。

### 每个线程独有的内容

- 程序计数器和寄存器现场。
- 栈及栈指针。
- 线程状态、线程 ID 和线程控制块 TCB。

线程分别执行不同函数、停在不同指令位置，因此必须独立保存自己的执行现场。口诀：**资源一起用，现场各自留。**

### 切换开销

- 进程切换通常需要切换 CPU 现场、地址空间和其他进程级环境。
- 同一进程内的线程共享地址空间和大部分资源，切换时主要保存和恢复线程执行现场。
- 因此线程切换通常比进程切换开销小，但并非没有开销。

### 并发与共享风险

- 单核 CPU 上多个线程通过切换实现并发；多核 CPU 上可能真正并行。
- 共享数据使线程通信方便，也会产生竞争条件。
- `count++` 包含读取、计算、写回多个步骤；若两个线程的步骤交错，可能发生丢失更新。

## 易错点

- 同一进程的线程不共享栈、栈指针、程序计数器或寄存器现场。
- 线程不是资源分配的基本单位；资源主要归进程所有，线程只是共享使用。
- 线程切换仍要保存和恢复执行现场，不能说“没有开销”。
- 多线程不代表线程必然同时执行；单核环境通常只是并发。
- “一个线程阻塞，其他线程一定能继续”不能脱离线程模型绝对判断。
- 多线程共享全局变量不保证复合读写操作具有原子性。

## 真题考法

- 判断资源分配单位和处理机调度单位。
- 判断同一进程线程之间哪些内容共享、哪些内容独有。
- 比较进程切换和线程切换的开销。
- 根据共享变量操作的交错过程判断可能结果。
