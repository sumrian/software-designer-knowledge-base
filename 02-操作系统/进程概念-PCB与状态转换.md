# 进程概念、PCB 与状态转换

> 模块：02 操作系统 ｜ 状态：🟦 待软件设计师回忆版真题校准

## 定义

进程是程序在某个数据集合上的一次动态执行过程。程序是静态的代码，进程则具有生命周期和运行状态。

进程实体通常由程序段、数据段和进程控制块（PCB）组成。PCB 是操作系统识别、管理和调度进程的核心数据结构，也是进程存在的标志。

## 要点

### PCB 保存什么

- 进程标识信息：PID、父进程等。
- 处理机现场：程序计数器、寄存器、状态字等；进程切换时需要保存和恢复。
- 进程状态与调度信息：运行/就绪/阻塞、优先级、队列指针等。
- 资源与管理信息：内存、打开文件、I/O 和记账信息等。

### 三态模型

- 运行态：正在占用 CPU 执行。
- 就绪态：除 CPU 外，运行条件已经具备，只等调度。
- 阻塞态：正在等待某个事件或资源，即使立即获得 CPU 也不能继续。

基本转换：

- 就绪 → 运行：被调度程序选中并获得 CPU。
- 运行 → 就绪：时间片到或被更高优先级进程抢占。
- 运行 → 阻塞：执行过程中申请的资源不足，或等待 I/O/事件。
- 阻塞 → 就绪：等待的资源或事件到达，只表示重新具备运行条件。

不能直接发生：

- 就绪 → 阻塞：就绪进程没有执行指令，不能主动发起会导致阻塞的操作。
- 阻塞 → 运行：事件完成只负责唤醒；还要先进入就绪队列，再经调度获得 CPU。

### P/V 与状态转换的最低限度理解

- P 操作用于申请资源：资源不足时，执行 P 的运行进程可能进入阻塞态。
- V 操作用于释放资源：可能唤醒一个等待者，使其阻塞态 → 就绪态；执行 V 的进程通常继续运行。

## 易错点

- “I/O 完成”不会让进程直接运行，只会使等待该 I/O 的进程阻塞 → 就绪。
- 一个进程释放设备，首先影响的是等待该设备的阻塞进程；不能据此默认释放者让出 CPU。
- 时间片到影响当前运行进程：运行 → 就绪；随后才由调度程序选择一个就绪进程运行。
- 多个进程同时处于就绪态时，谁先运行取决于题目给出的调度算法和队列顺序；题目未说明时不能擅自断言。
- PCB 不是进程的程序代码，而是操作系统保存其身份、状态、现场和资源信息的管理结构。

## 真题考法

- 根据事件判断单个进程的状态转换。
- 给出多个进程的初始状态与设备等待关系，连续跟踪事件后的状态。
- 判断哪些状态不能直接转换。
- 判断进程切换时 CPU 现场保存在哪里，或识别 PCB 的内容与作用。
