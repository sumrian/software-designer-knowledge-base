# 页面置换：抖动

## 定义

抖动（Thrashing，也称颠簸）是请求分页系统中一种严重性能退化现象：进程因获得的物理页框不足，频繁发生缺页，系统大量时间用于页面换入换出，而不是执行有效计算。

典型链路：

`页框不足 → 缺页频繁 → 页面换入换出增多 → 进程等待换页 I/O → CPU 利用率下降`

## 根本原因

抖动的核心不是“偶尔缺页”，而是**当前活跃进程所需要的页面集合无法稳定驻留内存**。

常见诱因：

- 多道程序度过高，同时活跃的进程太多；
- 每个进程可分配的页框太少；
- 进程当前局部性对应的工作集（Working Set）大于它实际拥有的页框数；
- 系统在 CPU 利用率下降后错误地继续增加并发进程，进一步压缩每个进程的页框。

## 工作集与局部性

程序在一段时间内通常只频繁访问一小部分页面，这体现局部性；这批近期活跃页面可用工作集来描述。

若某进程当前反复需要 4 个页面，但只获得 3 个页框，就可能出现：

`ABC → 访问 D 淘汰 A → 访问 A 淘汰 B → 访问 B 淘汰 C → …`

刚换出的页很快又被访问，缺页和页面置换持续发生，从而形成抖动。

## 抖动时 CPU 利用率为什么会下降

抖动发生时，大量进程因缺页而等待磁盘换页 I/O，CPU 反而没有足够的可运行进程，因此利用率下降。

这里有一个高频反直觉点：

> CPU 利用率低，不一定应该增加并发进程。若低利用率是抖动导致的，增加并发会让每个进程分到的页框更少，抖动可能进一步恶化。

## 缓解方法

核心目标是：**让活跃进程获得足够的页框，使其工作集尽量稳定驻留内存。**

常见措施：

1. 降低多道程序度，暂停或换出部分进程；
2. 将释放出的页框分配给剩余活跃进程；
3. 使用工作集模型估计进程当前需要的页面集合；
4. 使用缺页率 PFF（Page Fault Frequency）动态调节页框数；
5. 若条件允许，增加物理内存也能缓解页框不足。

## PFF 规则

PFF 用缺页率作为反馈信号：

- 缺页率高于上限 → 说明该进程页框可能不足 → **增加页框**；
- 缺页率低于下限 → 说明该进程页框可能富余 → **回收一部分页框**；
- 位于上下限之间 → 一般保持当前分配。

口诀：

> **PFF 高就加，PFF 低就收。**

## 易错点

- 抖动 ≠ 普通缺页；请求分页本来就允许正常缺页，抖动强调的是频繁缺页与严重性能下降。
- 抖动 ≠ Belady 异常；Belady 异常是某些置换算法中“页框增多反而缺页更多”的特殊现象，抖动是系统因内存压力和工作集放不下而频繁换页。
- 抖动时 CPU 利用率低，不能机械地认为“任务不够”而增加并发进程。
- 提高 CPU 主频、增大时间片、提高调度优先级都不能直接解决页框不足。
- PFF 低于下限时，直接动作是从该进程回收页框；“减少活跃进程”是系统整体发生抖动时的另一种缓解策略，不能混为同一个动作。

## 真题考法

常见题型是给出现象或资源变化，让判断：

- 多进程并发增加；
- 每进程页框减少；
- 缺页率和磁盘换页明显升高；
- CPU 利用率反而下降。

此时判断为抖动。

若问改善措施，优先选择：降低多道程序度、暂停部分进程、增加活跃进程可用页框、使用工作集/PFF 控制。
