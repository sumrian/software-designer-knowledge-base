# TCP 可靠传输：序号与字节流

## 定义

TCP 是面向字节流的传输协议。TCP 序号（seq）编号的是字节流中的字节位置，而不是“第几个 TCP 报文段”。

一个携带数据的 TCP 报文段，其 `seq` 表示该报文段中**第一个数据字节**的序号。

## 核心规则

若某报文段：

- 起始序号为 `seq = S`
- 携带 `L` 字节应用数据

则：

- 数据覆盖范围：`S ~ S + L - 1`
- 下一段连续数据的序号：`S + L`

例如 `seq=2500`、数据长度 `600B`：

- 本段覆盖 `2500 ~ 3099`
- 下一段连续数据 `seq=3100`

### SYN / FIN / ACK 对序号空间的影响

- 应用数据：按实际字节数推进序号。
- `SYN=1`：额外占用 1 个序号。
- `FIN=1`：额外占用 1 个序号。
- 单纯 `ACK=1`：**不额外占用序号**。

因此可用检查式：

`下一序号 = 当前 seq + 数据字节数 + SYN(0/1) + FIN(0/1)`

不要因为 `ACK=1` 再额外 `+1`。

## 易错点

1. **把 seq 当成报文段编号**：错误。TCP 按字节编号。
2. **范围终点漏掉 `-1`**：若从 `S` 开始放 `L` 个字节，最后一个序号是 `S+L-1`。
3. **把 ACK 标志也算作占用序号**：错误。普通 ACK 不额外推进序号。
4. **忘记 SYN / FIN 各占 1 个序号**：即使不携带应用数据，它们也占 TCP 序号空间中的一个位置。

## 真题考法

常见命题模型：

- 直接判断 TCP 序号的单位：字节。
- 给出 `seq` 与数据长度，求本段字节范围或下一段 `seq`。
- 混入 `ACK/SYN/FIN` 标志，判断哪些会额外消耗序号。
