# TCP 可靠传输：重传机制

## 定义

TCP 为了实现可靠传输，会保存尚未被确认的数据。当发送方判断某些数据可能没有被对方成功接收时，会重新发送这些数据，这就是**重传**。

本子考点重点掌握两类触发方式：

- **超时重传**：重传计时器 RTO 到期仍未得到有效确认。
- **快速重传**：经典考法中，连续收到 3 个重复 ACK 后，不等待 RTO 到期，立即重传 ACK 指向的缺失报文段。

## 核心规则

### 1. RTO 到期 → 超时重传

发送 TCP 报文段后，发送方会等待确认。如果在重传超时时间 RTO（Retransmission Timeout）到期前仍未收到有效确认，则对尚未确认的数据进行超时重传。

RTO 与网络往返时延 RTT 的估计有关，不应简单理解成永远固定不变的常数。

### 2. ACK 丢失也可能造成超时重传

即使接收方实际上已经收到数据，只要其 ACK 在网络中丢失，发送方仍可能因为迟迟收不到有效确认而在 RTO 到期后重传。

因此“超时”只能说明发送方没有及时得到确认，并不等价于能百分之百证明原数据报文段一定丢失。

### 3. 3 个重复 ACK → 快速重传

如果某个中间报文段丢失，但后续报文段陆续到达，接收方由于累计 ACK 不能跨越缺口，会反复返回同一个确认号。

经典 TCP 快速重传考法：

> 收到 3 个重复 ACK 后，不等待重传定时器超时，立即重传缺失报文段。

例如连续收到多个 `ACK=5000`，说明接收方下一步仍在等待从 `seq=5000` 开始的数据；满足快速重传门槛后，应优先重传该缺失位置对应的报文段。

### 4. 重复 ACK 指向“第一个缺口”

若接收方已收到 `1000~1499`，但 `1500~1999` 丢失，而 `2000~2999` 已先到达，则累计确认仍停在：

`ACK=1500`

所以重复 `ACK=1500` 的含义不是“1500 被收到了很多次”，而是接收方反复声明：**下一步仍缺 1500。**

### 5. 超时重传与快速重传的识别

- **RTO 到期** → 超时重传。
- **3 个重复 ACK** → 快速重传 ACK 指向的缺失报文段。

快速重传的核心价值是：已有重复 ACK 提供丢包线索时，不必继续等待 RTO 到期。

## 易错点

1. 不是出现一个重复 ACK 就立即快速重传；经典软考识别点是 **3 个重复 ACK**。
2. 重复 `ACK=N` 表示接收方仍在等待 `seq=N` 开始的数据，不是要重传 `N-1`。
3. RTO 到期时即使重复 ACK 数量不足，也应按超时重传处理。
4. ACK 丢失同样可能导致发送方超时重传。
5. 本子考点只识别重传触发机制，不把快速重传与更复杂的拥塞控制算法混在一起。

## 真题考法

常见题型包括：

- 判断 RTO 到期后发送方的动作。
- 给出中间报文段丢失和后续报文段到达的序列，判断重复 ACK 值。
- 给出 3 个重复 ACK，判断应快速重传哪个序号开始的报文段。
- 区分 ACK 丢失导致的超时重传与重复 ACK 导致的快速重传。
