# TCP 连接建立：三次握手

## 核心结论

典型三次握手：

1. A→B：`SYN=1, seq=x`
2. B→A：`SYN=1, ACK=1, seq=y, ack=x+1`
3. A→B：`ACK=1, seq=x+1, ack=y+1`

记忆：`SYN → SYN+ACK → ACK`。

## 序号与确认号

- `seq` 是发送方自己的序号。
- `ack` 表示下一步期望收到对方的序号。
- SYN 在 TCP 序号空间中占用 1 个序号，因此确认 SYN 时 `ack=对方 seq+1`。

## 为什么第二次是 SYN+ACK

服务器既要 ACK 确认客户端的 SYN，又要发送自己的 SYN，以完成双向连接建立信息的确认。
