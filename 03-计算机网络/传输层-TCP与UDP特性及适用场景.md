# 传输层：TCP 与 UDP 特性及适用场景

## 核心结论

- TCP：面向连接、可靠传输、面向字节流；提供确认、重传、按序交付、流量控制与拥塞控制等机制，协议状态与开销相对更大。
- UDP：无连接、尽力而为、面向数据报；不提供 TCP 那套完整的确认重传与按序交付机制，协议简单、开销较小。
- TCP 不保留应用层消息边界；UDP 保留数据报边界。
- 选型看需求：强调可靠、完整、按序时倾向 TCP；强调实时、低时延、允许少量丢失时倾向 UDP。
- TCP、UDP 都使用端口号实现进程寻址。

## 易错点

1. “UDP 不可靠”是指 UDP 本身不提供可靠交付保证，不等于应用层不能自行实现确认/重传。
2. “UDP 开销小”不应绝对化成任何情况下都一定比 TCP 快。
3. 消息边界：TCP 是连续字节流，不保证一次 send 对应一次 recv；UDP 以数据报为单位，保留报文边界。
