# 传输层：端口号与进程到进程通信

> 模块：03 计算机网络 ｜ 状态：🟦 待第二道合格回忆版真题校准

## 定义
传输层使用端口号区分同一主机上的不同应用进程或服务端点，实现进程到进程通信。网络层的 IP 地址负责定位主机，传输层的端口号负责把数据交给主机上的具体应用。

## 要点
- 端口号字段为 16 位，范围是 `0～65535`；其中 `0～1023` 通常称为熟知端口。
- IP 地址解决“数据送到哪台主机”，端口号解决“到达主机后交给哪个应用进程/服务端点”。
- 一次通信要同时区分源端口和目的端口；谁发送，谁的端口就是源端口，发给谁，谁的端口就是目的端口。
- 例如客户端 `52000 → 443` 发起请求，服务器回复时端口方向变为 `443 → 52000`。
- 发送端多个应用的数据可复用传输层；接收端根据目的端口号把数据分用到不同应用进程。
- `IP:端口` 可以表示一个通信端点，例如 `192.168.1.20:8080`。
- 常见服务端口示例：HTTP 默认 80，HTTPS 默认 443，DNS 常用 53。

## 易错点
- 端口号不是“进程本身”，而是传输层用于标识或区分应用进程/服务端点的编号。
- 不要混淆三层定位：MAC 地址主要服务于局域网帧转发，IP 地址定位主机，端口号定位应用进程/服务端点。
- 服务器/客户端角色不能只靠 IP 地址判断，应结合端口和通信上下文。
- 源端口与目的端口取决于当前报文方向，服务器回复时常见服务端口会从“目的端口”变成“源端口”。
- 接收端“根据目的端口把数据交给不同应用”的动作叫分用；多个应用共享传输层发送可理解为复用。

## 真题考法
- 端口号位数与范围：16 位、`0～65535`。
- 根据通信方向判断源端口、目的端口。
- 判断 IP 与端口各自解决的寻址层次。
- 根据目的端口号判断接收端应交给哪个应用进程。
- 判断 TCP、UDP 的共同能力中是否包含端口寻址。
- 常见服务默认端口号，例如 HTTP 80。
