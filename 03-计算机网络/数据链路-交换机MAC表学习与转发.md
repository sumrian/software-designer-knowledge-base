# 数据链路：交换机 MAC 表学习与转发

## 定义

交换机工作在数据链路层，普通二层转发主要依据目的 MAC 地址。交换机通过维护 MAC 地址表（MAC Table / CAM Table）记录 `MAC 地址 → 交换机端口` 的映射。

## 要点

- 交换机收到帧后，先根据**源 MAC + 入端口**学习或刷新 MAC 表项。
- 再查询目的 MAC：
  - 目的 MAC 已知且在其他端口：定向转发到对应端口。
  - 目的 MAC 未知：除入端口外向其他相关端口泛洪（未知单播泛洪）。
  - 目的 MAC 对应的端口就是入端口：过滤，不向其他端口转发。
- 动态 MAC 表项具有老化机制，用于适应主机移动和网络拓扑变化。

### 示例

初始 MAC 表为空：

1. 端口1收到 `A → B`：学习 `A → 1`，B 未知，因此泛洪。
2. 端口3收到 `B → A`：学习 `B → 3`，A 已知，因此只从端口1转发。
3. 再从端口1收到 `A → B`：B 已知在端口3，因此只从端口3转发。

## 易错点

- **学源，不学目的**：MAC 表学习依据是源 MAC 和入端口。
- 未知单播泛洪不等于广播帧；广播帧的目的 MAC 是 `FF:FF:FF:FF:FF:FF`。
- 泛洪通常不从入端口重新发回。
- MAC 表用于二层转发，不是路由器的 IP 路由表。
- 动态表项不会永久保留，长时间未使用会老化删除。

## 真题考法

常见命题模型：

1. 给定源 MAC、目的 MAC、入端口，判断交换机学习哪条表项。
2. 给定部分 MAC 表，判断已知单播、未知单播泛洪或同口过滤。
3. 连续给出多帧通信，追踪 MAC 表形成过程和下一帧的出端口。
4. 判断动态 MAC 表老化的作用。

口诀：**学源查目的；已知就定向，未知就泛洪，同口就过滤，久不用就老化。**
