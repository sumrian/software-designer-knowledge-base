# 网络层：IP 数据报与基本转发

## 定义

IP 工作在网络层，负责在不同网络之间进行无连接、尽力而为的数据报传递。路由器主要依据**目的 IP 地址**进行跨网络转发。

IP 本身不保证数据报一定到达、不保证按序到达，也不负责丢失后的重传；需要可靠传输时，通常由传输层协议（如 TCP）提供相应机制。

## IPv4 高频首部字段

- **源 IP 地址 / 目的 IP 地址**：标识通信两端。普通路由转发且不考虑 NAT 时，端到端通常保持不变。
- **TTL（Time To Live）**：每经过一个路由器减 1；若减到 0，路由器丢弃该数据报，防止路由环路导致无限转发。
- **Protocol（协议）字段**：说明 IPv4 数据报承载的上层协议，例如 `1=ICMP`、`6=TCP`、`17=UDP`。
- **首部校验和**：只校验 IPv4 首部，不覆盖整个数据报。路由器修改 TTL 后，需要重新计算首部校验和。
- **总长度**：表示整个 IPv4 数据报的长度。

## 基本转发过程

路由器收到一个链路层帧后，典型处理过程为：

1. 去掉当前链路层帧头/帧尾，取出 IPv4 数据报。
2. 读取目的 IP 地址，并根据路由表决定下一跳或出接口。
3. TTL 减 1；若结果为 0，则丢弃数据报。
4. 因 IPv4 首部发生变化，重新计算首部校验和。
5. 为下一跳重新封装新的链路层帧，使用这一跳对应的源/目的 MAC 地址。
6. 从选定接口发送。

## IP 与 MAC 的变化规律

在普通路由转发、忽略 NAT 的情况下：

- **源 IP / 目的 IP：端到端一般不变。**
- **源 MAC / 目的 MAC：逐跳改变。**
- **TTL：每经过一个路由器减 1。**
- **IPv4 首部校验和：因 TTL 变化而重新计算。**

可记：**路由看 IP，一跳换 MAC；TTL 每跳减，IP 负责送但不保送。**

## 易错点

- 路由器跨网络转发主要看目的 IP，不是看最终主机的目的 MAC。
- 下一跳路由器的 IP 地址通常不会替换 IPv4 数据报原来的目的 IP；改变的是当前链路层的目的 MAC。
- TTL 虽然名称中有“Time”，在常见考试模型中应按“每经过一个路由器递减”理解；**归零即丢弃**。
- IPv4 的首部校验和只覆盖首部，不是整个数据报。
- IP 是无连接、尽力而为服务，不保证可靠、按序和不重复；不能把 TCP 的可靠性特征套到 IP 上。

## 常见考法

1. 判断路由器转发前后哪些字段改变：IP、MAC、TTL、首部校验和。
2. 给定初始 TTL 和路由器数量，判断在哪一跳被丢弃。
3. 判断 Protocol 字段对应的上层协议。
4. 判断路由环路为何不会导致数据报永久循环。
5. 区分“端到端不变的 IP”与“逐跳变化的 MAC”。
