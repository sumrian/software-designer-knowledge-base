# 网络层：路由基础与路由表判定

## 定义

路由器收到 IP 数据报后，会根据**目的 IP 地址**查路由表，决定下一跳或出接口。路由表项通常可抽象为：

`目的网络/前缀长度 → 下一跳 → 出接口`

## 核心规则

### 1. 路由匹配看目的 IP

判断目的 IP 是否匹配某条路由，本质上可用：

`目的 IP AND 子网掩码 = 路由表中的网络地址`

例如目标地址 `192.168.1.77` 与路由 `192.168.1.0/24` 匹配，因为：

`192.168.1.77 AND 255.255.255.0 = 192.168.1.0`

### 2. 最长前缀匹配

当多条路由都能匹配目的 IP 时，选择**前缀长度最长**、也就是范围最具体的路由。

例如同时存在：

- `10.0.0.0/8`
- `10.1.0.0/16`
- `10.1.2.0/24`

目标 IP 为 `10.1.2.88` 时，应选择 `10.1.2.0/24`。

可记：**都能匹配时，选掩码最长的。**

### 3. 默认路由

`0.0.0.0/0` 是默认路由。它可以匹配任意 IPv4 地址，但优先级最低，通常仅在没有更具体路由可用时作为兜底。

### 4. 下一跳不是最终目的地址

路由表中的“下一跳”表示当前路由器先把数据交给哪台相邻路由器，不会把原 IP 数据报的最终目的 IP 改成下一跳地址。

这与前面已学规则一致：

**IP 端到端，MAC 逐跳换。**

## 判题流程

遇到路由表题，按顺序判断：

1. 用目的 IP 判断哪些路由能够匹配。
2. 在所有匹配项中选择最长前缀。
3. 根据选中的表项确定下一跳或出接口。
4. 若没有具体路由匹配，再考虑默认路由。

## 易错点

- 不按路由表书写顺序选择，而按最长前缀匹配。
- 默认路由不是优先路由，而是兜底路由。
- 路由匹配依据是目的 IP，不是源 IP，也不是目的 MAC。
- 下一跳地址不等于最终目的 IP。
- 多条路由都能覆盖目标地址时，应优先选更具体的前缀。
