# ER→关系模式：1:1 与 1:N 联系

> 模块：04 数据库系统 ｜ 状态：🟦（待真题校准与错题延迟复测）

## 定义

把 ER 模型中的一对一和一对多联系转换为关系模式，确定外键放置位置、联系属性归属及保持基数所需的约束。

## 要点

### 1:N 联系

- 将“一方”的主键加入“多方”关系，作为多方的外键。
- 联系自身的属性也随外键一起加入多方。
- 多方原有的码仍是主键；迁入的一方码通常只作为外键并允许重复。

示例：

```text
学院（学院号，学院名）
主键：学院号

教师（教师号，姓名，学院号，入院日期）
主键：教师号
外键：学院号 → 学院（学院号）
```

### 1:1 联系

- 可以把任意一方的主键加入另一方，作为外键；联系属性随之归并。
- 普通外键只保证引用对象存在，不能保证最多一次；迁入外键通常还需 `UNIQUE`。
- 若迁入一方必须参与联系，该外键还需 `NOT NULL`。
- 实际设计可优先选择全参与或依赖的一方，以减少空值并贴合生命周期。

约束职责：

```text
FOREIGN KEY → 引用对象必须存在
UNIQUE      → 同一对象最多被引用一次
NOT NULL    → 本记录必须参与联系
```

## 易错点

- 1:N 把外键放反：应是“一方码进多方”。
- 联系具有属性时，忘记把联系属性随外键放入多方。
- 把迁入外键误作多方主键；例如教师表的学院号允许重复，教师号仍是主键。
- 1:1 只写外键、不写 UNIQUE，会允许多个记录引用同一对象，破坏一对一（#错46）。
- “一方可以不参与”和“另一方必须参与”分别影响外键是否允许 NULL，不能混为一谈。
- 当前数据恰好一对一不等于业务规则保证一对一。

## 真题考法

- 根据 1:N 业务描述判断外键放置方。
- 填写主键、外键和联系属性。
- 判断 1:1 归并方案是否保持基数。
- 为 1:1 迁入外键补充 UNIQUE 与 NOT NULL。
