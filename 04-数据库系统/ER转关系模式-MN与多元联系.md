# ER→关系模式：M:N 与多元联系

> 模块：04 数据库系统 ｜ 状态：🟦 待真题校准

## 定义

M:N 联系和多元联系在转换为关系模式时，通常需要单独建立一个关系，用参与实体的码保存关联，并保留联系自身的属性。

## 要点

### 1. M:N 联系单独建表

若学生与社团之间是 M:N 联系“加入”，联系属性为加入日期，则转换为：

```text
加入（学号，社团号，加入日期）
主键：（学号，社团号）
外键：学号、社团号
联系属性：加入日期
```

两个实体的码都进入联系表并作为外键；在“一对实体组合只出现一次”的常见规则下，二者组成联合主键。

### 2. 同一组合可重复时加入区分属性

若同一学生可以在不同学期重复选修同一课程，则：

```text
选课（学号，课程号，学期，成绩）
主键：（学号，课程号，学期）
```

仅用“学号＋课程号”不能区分不同学期的记录，必须把学期加入主键。

### 3. 多元联系保留全部参与码和联系属性

供应商、项目和材料之间的三元联系“供应”，若联系属性为供应数量，典型转换为：

```text
供应（供应商号，项目号，材料号，供应数量）
```

三个参与实体的码都是外键；若三个编号缺一不可才能唯一确定一次供应，则三者组成主键。

### 4. 外键不一定全部属于主键

主键必须同时满足：

- 唯一性：能唯一标识一条联系记录。
- 最小性：去掉其中任一属性后不再唯一。

若业务规定每个“项目＋零件”组合只能指定一家供应商，则：

```text
项目采购（项目号，零件号，供应商号，采购单价）
主键：（项目号，零件号）
外键：项目号、零件号、供应商号
联系属性：采购单价
```

供应商号仍是外键，但“项目号＋零件号”已经唯一确定记录；再加入供应商号得到的是超码，不是最小候选码。

## 易错点

- 只写参与实体的码，漏掉报价、数量、用量等联系属性。
- 机械地认为多元联系的所有外键必须共同组成主键。
- 忽略学期、届次等使同一实体组合可以重复出现的区分属性。
- 仅凭“这是三元联系”确定主键；实际主键必须依据业务唯一约束判断。
- 把多元联系随意拆成若干二元联系，导致原有三方语义或约束丢失。

转换后使用清单逐项核对：

1. 参与实体的码是否全部作为外键带入？
2. 联系自身的属性是否全部带入？
3. 是否存在学期、届次等重复区分属性？
4. 主键是否唯一且最小？

## 真题考法

- 给出 M:N ER 联系，要求补充联系关系的属性、主键和外键。
- 给出带联系属性的二元或多元联系，判断哪些属性必须保留。
- 给出“同一组合可在不同学期或届次重复”的规则，要求补全联合主键。
- 给出三元联系及业务唯一约束，判断参与实体码是否全部属于主键。
