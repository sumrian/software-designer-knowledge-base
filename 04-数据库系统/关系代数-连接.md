# 关系代数：连接

> 模块：04 数据库系统 ｜ 状态：🟦 待真题校准

## 定义

连接把两个关系中满足关联条件的元组组合起来。常见相关运算包括笛卡尔积、θ 连接、等值连接和自然连接。

## 要点

### 1. 笛卡尔积产生全部配对

若关系 (R) 有 (m) 个元组、(r) 个属性，关系 (S) 有 (n) 个元组、(s) 个属性，则在属性名不冲突或已区分的情况下：

[
|R	imes S|=m	imes n
]

结果属性数为：

[
r+s
]

笛卡尔积不判断配对是否有业务意义。

### 2. θ 连接等价于笛卡尔积后选择

[
Rowtie_{	heta}S
=
sigma_{	heta}(R	imes S)
]

先产生全部组合，再保留满足连接条件的组合。θ 可以是等于、不等于、大于、小于等比较符号。

### 3. 等值连接

当 θ 连接使用等号条件时称为等值连接：

[
Rowtie_{R.A=S.B}S
]

等值连接通常保留双方参与比较的两个属性，即使它们取值相同。

### 4. 自然连接

自然连接 (Rowtie S)：

1. 找出双方全部同名属性；
2. 要求每个同名属性的值都相等；
3. 组合匹配元组；
4. 结果中重复的同名属性只保留一列。

例如：

```text
R（学号，课程号，成绩）
S（学号，课程号，教材号）
```

自然连接要求学号相等且课程号相等，结果属性为：

```text
（学号，课程号，成绩，教材号）
```

此规则只依据属性名称和值，不依赖主键、外键或唯一约束声明。

### 5. 无同名属性的边界

若两个关系没有任何同名属性，自然连接没有相等条件可用于筛选，因此退化为笛卡尔积：

[
Rowtie S=R	imes S
]

如果存在同名属性，但没有任何同名属性值匹配，结果才可能为空。

### 6. 连接结果规模

[
|Rowtie_{	heta}S|le |R|	imes|S|
]

实际元组数取决于匹配情况：

- 无匹配：0 行；
- 一对一：每次匹配产生一行；
- 一对多或多对多：一个元组可能参与多次组合；
- 无同名属性的自然连接：达到笛卡尔积规模。

## 易错点

- 把笛卡尔积误认为会自动筛选关联元组。
- 认为等值连接会自动删除重复连接属性；自动合并同名列的是自然连接。
- 认为自然连接只任选一个同名属性；实际是所有同名属性都必须相等。
- 把自然连接规则误认为依赖主键、外键或唯一性声明。
- 认为没有同名属性时自然连接结果为空；实际退化为笛卡尔积。
- 忽略“同名但不同义”属性；直接自然连接可能增加错误条件，应重命名或明确写连接条件。
- 用双方元组数相乘直接断定普通连接结果；只有笛卡尔积规模可以直接相乘。

口诀：

> 积是全部配对，连接是配对后筛选；自然连接找全部同名，无同名就退化为积。

## 真题考法

- 根据两个关系的属性数和元组数计算笛卡尔积规模。
- 识别 (Rowtie_{	heta}S=sigma_{	heta}(R	imes S))。
- 区分等值连接与自然连接是否合并重复属性。
- 给出关系实例，计算自然连接的属性集合和全部元组。
- 判断多个同名属性是否全部参与自然连接。
- 考查无同名属性时自然连接退化为笛卡尔积的边界。
