# 从需求提取属性与操作

## 定义
- 属性描述对象需要保存或表达的信息、特征和状态；UML 常用“可见性 名称: 类型”。
- 操作表达对象承担的行为或服务；UML 常用“可见性 名称(参数名: 参数类型): 返回类型”。

## 要点
- 从需求提取编号、名称、数量、状态等候选属性；结合业务含义选取类型。
- 从职责与业务规则提取操作；操作不仅是动词，还应负责适当的状态变更与约束检查。
- 业务实体优先维护自身状态与规则；涉及外部系统协作的流程可由 Service 承担，具体仍依职责判断。
- Java 示例：
```java
class Order {
    private String orderId;
    private OrderStatus status;
    public void cancel() {
        if (status == OrderStatus.PAID) throw new IllegalStateException("已支付不可取消");
        status = OrderStatus.CANCELLED;
    }
}
```
- 对应 UML：`- orderId: String`、`- status: OrderStatus`、`+ cancel(): void`。
- Java 参数语法为“类型 参数名”，UML 参数语法为“参数名: 类型”。

## 易错点
- 机械地把名词都变成属性或动词都变成操作；要看对象职责。
- 混淆属性与操作，例如把取消订单设计为布尔属性，而忽略取消行为。
- 将数据库连接、页面展示等技术职责放入领域实体。
- 忽略业务约束：例如最多借 5 本，借阅操作应检查上限。
- 可派生的信息不一定需要重复存储，避免状态不一致。

## 真题考法
- 根据需求补全类的属性或操作；根据 Java 声明补全 UML 成员签名；识别操作职责归属。
