# 序列图基本结构与生命线

## 定义
序列图（Sequence Diagram）是 UML 交互图，用于表达参与交互的对象或角色之间的消息及其时间顺序。生命线（Lifeline）表示一个交互参与者在交互中的存在，通常为顶部标识和向下延伸的竖直虚线。

## 要点
- 序列图通常按从上到下的纵向位置表示消息发生的先后；横向区分交互参与者，不代表时间。
- 生命线标识可写为 `对象名:类型名`，如 `order:Order`；`:Order` 表示匿名的 Order 类型参与者。
- 同一 Java 类型的不同对象可以拥有不同生命线，如 `order1:Order` 与 `order2:Order`。
- 生命线虚线表示参与者在交互中的存在；附着于其上的细长矩形为执行规格，表示执行某段行为的区间。
- 生命线的选取由当前交互场景决定，不是每个 Java 类、参数或方法都必须有生命线。

## Java/UML 案例
```java
class CourseController {
    CourseService service;
    Course getCourse(Long id) { return service.findById(id); }
}
class CourseService {
    Course findById(Long id) { return new Course(id); }
}
```
若只描述学员查询课程且不展示 Course 创建，高层序列图可选学员、controller:CourseController、service:CourseService 三条生命线。交互按纵向先后表示：学员请求 → Controller 调用 Service → Service 返回 → Controller 返回给学员。

## 易错点
- 颠倒对象名和类型名。
- 将生命线当成 Java 类继承关系或执行规格。
- 将横向箭头方向误认为时间先后。
- 将同类型的不同交互对象强制合并成一条生命线。
- 将每个 Java 类、方法或参数都机械地画成生命线。
- 根据图上纵向距离直接计算实际运行耗时。
