# 序列图对象创建与销毁

## 定义
UML 序列图可通过创建消息（Create Message）与销毁消息（Delete Message）表达交互参与对象的生命周期。新对象生命线从创建消息到达对象头部的位置开始；对象销毁时以 X（Destruction Occurrence）标记生命线终止。

## 要点
- 创建消息指向新对象的生命线头部，创建之前不应绘制该对象的生命线。
- 创建后可继续接收普通消息；执行规格的结束不意味着对象被销毁。
- 销毁消息到达对象后，生命线在 X 处终止；不应在 X 后继续向已销毁对象发送普通消息。
- Java 引用置空仅改变引用，不代表对象立即销毁；即使对象不可达，GC 也不保证立即执行。
- close()/logout()/remove() 不必然表示 Java 对象销毁；须根据明确的业务建模语义判断是否绘制 X。

## Java/UML 案例
```java
Order order1 = new Order();
Order order2 = order1;
order1 = null;
order2.validate();
```
order1 和 order2 起初引用同一个 Order 对象，置空 order1 后仍可通过 order2 调用 validate()，不能据此在生命线上绘制 X。

临时任务系统：TaskManager 创建 Task，调用 execute()，执行完成后 Task 仍然存在；若需求明确 TaskManager 随后发送销毁消息，则 Task 生命线在 X 处终止。创建消息指向 task:Task 头部；execute() 返回只结束相应执行规格，不终止对象生命线。

## 易错点
- 将新对象生命线错误地从图顶部绘制，创建消息却指向其中段。
- 把 X 当作创建成功、方法执行结束或返回消息。
- 认为执行规格结束必然销毁对象。
- 认为 order = null、close() 或方法返回自动意味着 Java 对象被立即 GC。
- 在 X 后继续绘制对已销毁对象的普通消息。
