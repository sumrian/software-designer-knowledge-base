# 序列图执行规格与调用嵌套

## 定义
执行规格（Execution Specification，常称激活条）是在 UML 序列图生命线上表示交互参与者执行某段行为区间的细长矩形。生命线表示参与者存在，执行规格表示执行区间。

## 要点
- 普通同步调用时，接收方的执行规格通常在接收到调用消息时开始，在该次处理完成、返回时结束。
- A 同步调用 B、B 再同步调用 C 时，A 与 B 的外层执行规格可以持续，形成时间上的嵌套，不要求调用方先结束执行规格。
- 同一对象可以向自己发送自消息，调用自身其他方法；自消息不一定是递归。
- 递归要求某方法直接或间接再次调用自身，可在同一生命线上用错位的嵌套执行规格表示。
- Java 调用栈可辅助理解同步调用嵌套，但与 UML 执行规格不是同一概念；异步、多线程等场景不能机械对应。
- 不必每次都画出所有执行规格，也不能用矩形长度直接计算运行耗时。

## Java/UML 案例
```java
class OrderController {
    OrderService service;
    Order submit(OrderRequest request) {
        return service.createOrder(request);
    }
}
class OrderService {
    InventoryService inventory;
    Order createOrder(OrderRequest request) {
        boolean reserved = inventory.reserveStock(request);
        if (!reserved) throw new IllegalStateException();
        return saveOrder(request);
    }
    private Order saveOrder(OrderRequest request) {
        return new Order();
    }
}
```
- Controller.submit() → OrderService.createOrder() → InventoryService.reserveStock() 均为同步调用；InventoryService 执行时，外层两段执行规格可以继续存在。
- reserveStock() 返回后，OrderService 原执行规格继续；saveOrder() 可以用同一 OrderService 生命线的同步自消息与嵌套执行规格表达，不是递归。
- Service 返回订单后，Controller 继续完成 submit()。

## 易错点
- 将细长矩形误认为对象完整生命周期、类继承关系或数据库事务。
- 将等待下层同步调用误认为外层执行规格必须结束。
- 认为同一时刻只能有一个生命线存在执行规格，或执行规格重叠必然多线程并行。
- 认为每个 Java 方法都必须有独立生命线。
- 认为所有自消息都是递归；将自消息错误建模为异步消息。
- 将执行规格的纵向长度当作真实耗时。
