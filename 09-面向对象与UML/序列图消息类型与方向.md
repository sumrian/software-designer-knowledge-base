# 序列图消息类型与方向

## 定义
UML 序列图中的消息表示交互参与者之间的通信，箭头指向接收方，纵向位置表达时间先后。本考点重点辨析同步消息、异步消息与返回消息。

## 要点
- 同步消息：实线加实心三角箭头；调用方等待被调用方完成。
- 异步消息：实线加开放箭头；发送方不必等待接收方处理完成。
- 返回消息：虚线加开放箭头；结果或控制返回原调用方，通常可以省略。
- 消息箭头方向表示接收方，不表示时间先后；时间通常从上向下。
- 不能仅凭 Java 方法名、Event、Queue 字样判断是否异步，必须依据实际调用语义。

## Java / UML 案例
```java
boolean valid = paymentService.verify(order); // 同步调用
if (valid) eventPublisher.publishAsync(new OrderCreatedEvent(order)); // 已明确异步
updateStatistics();
```
- OrderService → PaymentService：verify() 同步消息，实线实心三角。
- PaymentService → OrderService：valid:boolean 返回消息，虚线开放箭头。
- OrderService → EventPublisher：publishAsync() 异步消息，实线开放箭头。
- 上述异步性来自场景明确约定，不由方法名直接推出。

## 易错点
- 将同步消息误画成实线开放箭头。
- 将异步消息误画成虚线，混淆返回消息。
- 认为 Java 所有方法调用都同步，或方法名有 Async 就必然异步。
- 将返回消息误认为新的同步调用。
- 因为返回箭头朝左，就将返回消息画在调用消息之前。
- 误认为所有返回消息都必须绘制。
