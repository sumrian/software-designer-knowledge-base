# 用例与参与者的泛化关系

## 定义
UML 用例图中的泛化（Generalization）表示一般与特殊的关系，可用于参与者之间，也可用于用例之间。使用**实线加空心三角**，箭头从特殊元素指向一般元素。

## 要点
- **参与者泛化**：特殊参与者继承一般参与者的公共用例关联，并可具有自己的专有用例。兄弟角色不会自动继承彼此的专有能力。
- **用例泛化**：特殊用例是一般用例的特化，继承共同业务行为和关系，并可定义自己的特殊处理。
- **箭头方向**：特殊 → 一般，空心三角指向父级/一般元素。
- **语义辨析**：泛化表示“是一种”；include 表示基础用例包含必需行为；extend 表示条件性添加扩展行为。
- **建模边界**：两个角色共享部分权限不必然存在泛化；Java extends 只是理解类比，不能机械映射到用例图。

## Java / UML 案例
在线教育系统中，Student 与 Teacher 是 User 的特殊参与者：
- Student ──▷ User；Teacher ──▷ User。
- User 可查看个人资料；Student 继承该关联且可报名课程；Teacher 继承该关联且可录入成绩。
```java
class User { void viewProfile() {} }
class Student extends User { void enrollCourse() {} }
class Teacher extends User { void submitGrades() {} }
```
代码仅用于理解一般与特殊；参与者不是必须对应 Java 类。

支付系统中，银行卡支付、数字钱包支付均泛化到一般用例「支付订单」；如果「验证支付金额」是共同必需行为，可以建模为「支付订单」通过 «include» 指向「验证支付金额」。

## 易错点
- 将泛化空心三角指向特殊元素。
- 将一般参与者的关联继承误解为兄弟角色间权限共享。
- 将用例泛化误认为 include 或 extend，或误认为执行顺序。
- 仅凭两个角色有相同权限便建立泛化。
- 将 Java 类继承与 UML 参与者/用例泛化一一对应。
