# 用例之间的包含关系 include

## 定义
UML 用例之间的包含关系（«include»）表示基础用例的行为定义中包含另一个用例的行为；常用于抽取必需的、值得独立表达的公共业务行为。虚线依赖箭头从基础用例指向被包含用例。

## 要点
- **方向**：基础用例 ──«include»──→ 被包含用例；谁包含谁，箭头指向被包含者。
- **必需行为**：基础用例执行过程中包含被包含用例定义的行为；验证失败可以中止业务，不代表该行为可选。
- **复用**：多个基础用例可以包含同一个公共用例，但不要求至少两个基础用例；一个基础用例也可以包含一个独立校验用例。
- **业务粒度**：不是每个技术步骤、SQL、HTTP 响应或 Java 方法调用都应抽取为独立用例；由建模目的决定。
- **执行顺序**：«include» 不负责完整描述多个行为的先后顺序，需借助用例规约或活动图等进一步表达。

## Java / UML 案例
银行业务“账户转账”和“修改银行卡信息”均必须进行身份验证，且业务模型将验证身份独立抽取：
- 账户转账 ──«include»──→ 验证身份
- 修改银行卡信息 ──«include»──→ 验证身份

```java
class SecurityService {
    void verifyIdentity(User user) { /* 验证身份 */ }
}
class BankService {
    SecurityService security;
    void transfer(User user) {
        security.verifyIdentity(user);
        // 执行转账
    }
    void changeCard(User user) {
        security.verifyIdentity(user);
        // 修改银行卡信息
    }
}
```
代码只用于解释行为复用，不能仅凭方法调用推断 UML include。

## 易错点
- 把箭头画反，错误地让被包含用例指向基础用例。
- 以执行先后顺序决定 include 箭头方向。
- 认为必须有多个基础用例才能使用 include。
- 把所有内部操作都抽取为被包含用例，混淆需求模型与代码实现。
- 把 include 误认为泛化或普通关联。
