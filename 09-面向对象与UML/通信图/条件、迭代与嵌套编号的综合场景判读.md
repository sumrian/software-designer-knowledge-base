## 定义
通信图以对象链接和带编号的消息表达交互。迭代标记 `*` 描述重复发送；守卫 `[condition]` 限制消息是否实际发送；小数点分层编号表示消息调用的直接父子层级。

## 要点
1. 先按 Java 循环计算遍历次数，再逐层应用守卫，得到每条消息实际调用次数。
2. 子消息执行的前提是其父消息确实发生；没有独立守卫也不能绕过父消息。
3. `1.1.1` 和 `1.1.2` 同级，直接父级均为 `1.1`；`1.1.1.1` 的直接父级为 `1.1.1`，而 `1.1` 是祖先。
4. 编号帮助判断调用嵌套，不应仅凭同一业务流程就断言消息同级。

## Java 案例
```java
void processRefunds(List<Refund> refunds) {
    for (Refund refund : refunds) {
        if (refund.isApproved()) handleRefund(refund);
    }
    generateReport();
}
void handleRefund(Refund refund) {
    if (refund.requiresAudit()) auditRefund(refund);
    executeRefund(refund);
}
void auditRefund(Refund refund) {
    if (refund.isHighRisk()) notifyRiskTeam(refund);
}
```
数据 R1(true,true,true)、R2(true,false,true)、R3(false,true,true)、R4(true,true,false)、R5(true,true,true)，属性依次为 approved、requiresAudit、highRisk。

消息：
```text
1: processRefunds()
1.1 *[i=1..5] [approved]: handleRefund()
1.1.1 [requiresAudit]: auditRefund()
1.1.1.1 [highRisk]: notifyRiskTeam()
1.1.2: executeRefund()
2: generateReport()
```
实际次数：handleRefund 4、auditRefund 3、notifyRiskTeam 2、executeRefund 4、generateReport 1。R2 的 highRisk 虽为 true，但不进入 auditRefund，不能触发 notifyRiskTeam。

## 易错点
- 把循环 5 次误判为带守卫的父消息必然发送 5 次。
- 忽略父级守卫，认为无独立守卫的子消息每轮必执行。
- 将直接父级与高层祖先混淆；将共同祖先误当同级。
