## 定义
序列图和通信图都是 UML 交互图，描述同一组对象之间的交互。序列图强调消息的纵向时间顺序与生命线；通信图强调对象链接及编号消息。转换要保持交互语义，而非图形布局。

## 要点
1. 保留对象、消息发送者与接收者、消息名称及参数。
2. 序列图的时间与调用嵌套转换为通信图的编号：1 的直接子消息依次为 1.1、1.2；1.1 的子消息为 1.1.1。
3. 反向转换按编号还原调用嵌套和先后关系。
4. 保留条件守卫和迭代语义。带守卫的循环消息实际调用次数取决于每次迭代的条件是否成立。
5. 自调用可以表示为对象向自身发送消息。

## Java 示例
```java
void processBatch(List<Order> orders) {
    for (Order order : orders) {
        if (order.isValid()) payment.pay(order);
        audit.record(order);
    }
    finishBatch();
}
```
通信图：1 processBatch；1.1 *[valid] pay；1.2 * record；1.3 finishBatch。若三个订单有效性依次为 true、false、true，则 pay 2 次、record 3 次、finishBatch 1 次。

## 易错点
- 不得把兄弟消息错误编号成父子消息，或把子消息提升为顶层消息。
- 不得反转消息方向。
- 不得丢失守卫条件或将其扩大到不受条件控制的消息。
- 循环次数不必等于受守卫约束的消息实际调用次数。

## 真题考法
给定 Java/序列图判断通信图编号、方向、守卫；给定通信图还原序列图；比较两图是否保持条件与层级语义。当前均为原创模拟，合规回忆版真题 0/2，未声称有已核验年份场次。
