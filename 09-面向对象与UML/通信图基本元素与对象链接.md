# 通信图基本元素与对象链接

## 定义
UML 通信图（Communication Diagram，UML 1.x 中常称协作图）是交互图，强调参与交互的对象及对象间用于传递消息的链接。对象表示参与者，链接表示通信路径，消息表示具体交互。

## 要点
- 对象常用 `对象名:类名` 表示，如 `service:OrderService`；匿名对象可用 `:OrderRepository`。
- 链接表示对象之间可用于通信的连接，不是方法调用，也不直接等于继承或永久类关联。
- 同一条链接可承载多条消息；具体调用、方向及顺序须由消息信息表达。
- 从 Java 代码沿调用链逐层识别发送方与接收方，不因对象共同参与业务就补画两两链接。
- 方法参数传入的对象引用也可支持接收方对该对象的直接调用；传递引用本身不等于发送方直接调用该对象。
- 与序列图相比，通信图更强调对象组织和链接拓扑，执行顺序通常通过消息编号表达。

## Java/UML 案例
```java
class CheckoutService {
    private PaymentService paymentService;
    private OrderRepository orderRepository;
    void checkout(Order order) {
        paymentService.pay(order);
        orderRepository.save(order);
    }
}
class PaymentService {
    private PaymentGateway gateway;
    void pay(Order order) {
        gateway.charge(order.getAmount());
        order.markPaid();
    }
}
```
当前场景有五个对象，四条有依据的直接通信链接：
- CheckoutService — PaymentService：pay(order)
- CheckoutService — OrderRepository：save(order)
- PaymentService — PaymentGateway：charge(amount)
- PaymentService — Order：markPaid()

不要凭借同属一次结算流程添加所有对象两两链接；`order` 作为参数可供 PaymentService 调用，但不代表 CheckoutService 在该方法中直接调用 order 的方法。

## 易错点
- 把 Java 方法当成对象框。
- 将链接直接视为一次消息、执行顺序或继承关系。
- 认为一条链接只能承载一条消息。
- 认为通信图链接必然意味着类图中永久双向关联。
- 漏掉通过参数引用发生的直接调用，或把参数传递误当直接调用。
- 按业务重要性而不是实际调用关系增加链接。
