# 通信图条件消息与守卫标记

## 定义
通信图中的守卫条件（guard）用于约束某条消息是否在给定条件下发送。常见写法是在消息编号后标注方括号条件，例如 `1.2 [available]: save(order)`。

## 要点
- 守卫为真时，对应消息可以按交互逻辑发送；守卫为假时，跳过该条受守卫约束的消息。
- 守卫作用于对应消息，不会自动终止整个交互，也不会自动取消后续没有该守卫的公共消息。
- 对象链接表示对象之间可能的通信连接；某次受守卫约束的消息未发送，不意味着链接自动消失。
- 消息编号是图上的静态顺序/层级标记。某条消息因守卫为假而跳过时，其他消息编号不会自动重新编号。
- if/else 可用互斥守卫表示，例如 `[isPaid]` 与 `[!isPaid]`；分支之后的公共消息应独立表示，保留原程序控制流语义。

## 案例
Java：
```java
if (order.isPaid()) {
    paymentService.confirm(order);
} else {
    paymentService.requestPayment(order);
}
notificationService.notifyUser(order);
```

通信图消息：
```text
1.1 [isPaid]: confirm(order)
1.2 [!isPaid]: requestPayment(order)
1.3: notifyUser(order)
```

当 `order.isPaid()` 为 false 时，跳过 1.1，发送 1.2；公共消息 1.3 仍按自身执行逻辑处理，编号不变。

## 易错点
- 把守卫条件误认为作用于整条对象链接。
- 认为某条消息未发送会导致后续消息自动跳过。
- 认为跳过消息后需要给后续消息重新编号。
- 忽略互斥分支之后仍可能存在公共消息。

## 真题考法
- 根据守卫真假判断哪条消息发送、哪条跳过。
- 判断守卫对链接、后续公共消息及静态编号的影响。
- 把 Java 的 if/else 控制流映射到通信图，并检查互斥分支与公共消息是否保留。
