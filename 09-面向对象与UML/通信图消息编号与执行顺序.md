# 通信图消息编号与执行顺序

## 定义
UML 通信图使用消息编号表达交互消息的执行顺序及调用嵌套层级。序列图通常通过纵向位置表达时间，而通信图主要通过消息编号确定先后与所属调用。

## 要点
- 同一层级的顺序消息可依次编号 1、2、3；同一链接可以承载多条不同编号的消息。
- 若外层调用编号为 1，则处理期间直接发起的子调用为 1.1、1.2；1.1 内部发起的调用可编号 1.1.1。
- 编号不是小数、调用次数或对象坐标；前缀表达所属调用，末段表达该层级中的次序。
- 调用返回后，后续消息恢复到实际调用方的层级编号，不会因时间变晚而不断加深。
- 本轮以同步、正常返回的 Java 调用为例；异步、并发情形不能机械视为全局串行。

## Java/UML 案例
```java
class OrderService {
    PaymentService payment;
    OrderRepository repository;
    void process(Order order) {
        payment.pay(order);
        repository.save(order);
    }
}
class PaymentService {
    PaymentGateway gateway;
    AuditService audit;
    void pay(Order order) {
        gateway.charge(order.getAmount());
        audit.recordPayment(order);
    }
}
class PaymentGateway {
    BankClient bank;
    void charge(BigDecimal amount) {
        bank.transfer(amount);
    }
}
```
假设 Controller 调用 process() 编号为 1，则依次为：
- 1: process()
- 1.1: pay()
- 1.1.1: charge()
- 1.1.1.1: transfer()
- 1.1.2: recordPayment()
- 1.2: save()

transfer() 属于 charge()；recordPayment() 在 charge() 返回后仍属于 pay()；save() 在 pay() 返回后属于 process()。

## 易错点
- 将嵌套调用全部平铺为全局 1、2、3。
- 把 1.1 当作小数或执行次数。
- 因消息发生更晚就错误加深层级。
- 将 charge() 的子消息误列为 pay() 的同层级消息。
- 因调用同一对象就误认为消息之间互相嵌套。
- 忽略同步调用返回后恢复父层级。
