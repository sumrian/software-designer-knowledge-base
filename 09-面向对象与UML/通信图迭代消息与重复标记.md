## 定义

通信图用消息标记中的 `*` 表示该消息按指定规则重复发送或执行。迭代范围、集合或条件用于说明重复的依据；消息编号仍用于表达消息的层次与顺序，不是执行次数。

## 要点

- `1: process()`：普通消息，本身没有声明迭代。
- `1*: process()`：迭代消息；只有 `*` 时不能据此确定具体重复次数。
- `2*[i=1..4]: sendNotification(i)`：按题目给定范围，i 依次取 1、2、3、4，共执行 4 次；编号 `2` 不表示执行 2 次。
- `[valid]` 是判断消息是否发送的守卫条件，本身不等于重复执行；`*` 才是本考点的迭代标记。
- `[item in items]` 一类表达式可以说明遍历集合。具体次数取决于题目给定的集合或迭代规则；集合为空时可能执行 0 次。
- 迭代标记约束它所修饰的消息，不能自动把循环外的日志、审计等普通消息也理解为重复消息。

## 完整案例：逐条保存订单，结束后记录一次审计

```java
for (Order order : orders) {
    repository.save(order);
}
auditService.recordBatchCompleted();
```

恢复上一轮案例的含义：`1.1*: save(order)` 对应逐条保存订单的重复调用；循环外的审计调用是普通消息，不加重复标记。

推导：先看哪些动作位于循环体内，再识别它们的消息接收对象与调用；只有随每个订单重复的保存消息需要迭代标记。批次结束后的公共审计只执行一次，不因保存消息带 `*` 就一并重复。

## 易错点

1. `*` 不表示异步、并行，也不是类图的关联多重度标记。
2. `*` 不意味着无限循环，更不能仅据星号断言至少执行一次。
3. `[条件]` 与 `*[迭代规则]` 不能混为一谈：前者判断是否发送，后者说明重复执行。
4. 消息编号表达顺序和嵌套层次，实际执行次数应从迭代规则判断。
5. 先区分循环体与循环后动作，不要把后续消息全部当作迭代消息。
